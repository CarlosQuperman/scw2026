지문 읽기 전 10분 개념 지도

“메모리는 왜 부족하고,
페이지는 왜 교체할까?”

CPU → RAM → SSD/HDD라는 컴퓨터의 기억공간 구조에서 출발해, 가상 메모리, 페이지 히트·페이지 폴트, FIFO/LRU/LFU, 그리고 GPU와 HBM까지 한 번에 연결해 봅니다.

1. 먼저, 컴퓨터의 기억공간을 ‘책상’으로 생각해 보자

컴퓨터가 일을 할 때 모든 자료를 똑같은 장소에 놓는 것은 아닙니다. 빠르게 꺼내야 하는 것은 가까운 곳에, 많이 보관해야 하는 것은 멀리 둡니다.

CPU 내부

가장 빠름 · 가장 작음

계산에 바로 쓰는 레지스터와 캐시가 있습니다. CPU가 손을 뻗으면 거의 바로 닿는 ‘손 위의 메모장’입니다.

주기억장치 RAM

빠름 · 수 GB~수십/수백 GB

실행 중인 프로그램과 데이터를 올려놓는 ‘책상’입니다. 전원이 꺼지면 내용이 사라집니다.

보조기억장치

RAM보다 느림 · 수백 GB~수 TB+

SSD, HDD, USB 저장장치 등이 여기에 해당합니다. 오래 보관할 수 있지만 RAM보다 접근이 느립니다.

핵심 관계: 대체로 CPU 내부의 레지스터·캐시 → RAM → SSD/HDD 순서로 갈수록 저장공간은 커지고, 접근 속도는 느려집니다. 단, USB는 연결 방식과 장치에 따라 속도 차이가 크므로 ‘항상 HDD보다 빠르다/느리다’라고 단정하면 안 됩니다.
SSD/HDD많이 저장
→
RAM실행할 것 올리기
→
CPU계산하기

여기서 지문의 ‘주기억장치’는 보통 RAM을 뜻합니다. CPU 자체를 주기억장치라고 부르는 것은 아닙니다.

2. 그런데 RAM보다 큰 프로그램을 실행하면?

예를 들어 RAM이 8GB인데 프로그램 전체가 12GB를 필요로 한다고 생각해 봅시다. 프로그램 전체를 RAM에 한꺼번에 넣을 수 없습니다.

4. 페이지 히트 vs 페이지 폴트

CPU가 “페이지 B를 주세요!”라고 요청했다고 생각해 봅시다. 가장 중요한 것은 그 페이지가 지금 RAM에 있느냐입니다.

PAGE HIT

찾았다!

요청한 페이지가 이미 RAM의 페이지 프레임에 있습니다.

CPU 요청
→
RAM에 있음 ✓
→
바로 사용

빠릅니다. SSD까지 다녀올 필요가 없습니다.

PAGE FAULT

없다!

요청한 페이지가 RAM에 없습니다.

CPU 요청
→
RAM에 없음 ✕
→
SSD에서 가져오기

느립니다. 필요하면 빈 프레임을 쓰거나 기존 페이지를 교체해야 합니다.

시험에서 기억할 한 문장: 페이지 히트 = 필요한 페이지가 RAM에 있음 / 페이지 폴트 = 필요한 페이지가 RAM에 없음. 페이지 폴트가 발생하면 보조기억장치에서 페이지를 가져오는 작업이 필요할 수 있습니다.

5. RAM이 꽉 찼다면? → 페이지 교체

새 페이지 D가 필요한데 페이지 프레임 3개가 이미 A, B, C로 꽉 찼다면 누군가는 자리를 비워 줘야 합니다.

FIFO

“먼저 들어온 것부터 나가!”
가장 먼저 RAM에 들어온 페이지를 교체합니다.

LRU

“가장 오래 안 쓴 것을 나가!”
최근 사용 시점이 가장 오래된 페이지를 교체합니다.

LFU

“가장 적게 쓴 것을 나가!”
사용 횟수가 가장 적은 페이지를 교체합니다. 동률이면 추가 규칙이 필요합니다.

지문의 예시를 연결하면: A, B, C가 RAM에 있고 사용 순서가 A → B → C → B → A라면 D가 들어올 때 FIFO는 A, LRU는 C, LFU도 사용 횟수가 가장 적은 C를 교체합니다.

6. 그런데 GPU 시대에는 HBM이 등장한다

HBM(High Bandwidth Memory)은 이름 그대로 ‘높은 대역폭의 메모리’입니다. 기존 RAM과 완전히 다른 종류의 ‘마법 메모리’라기보다, GPU가 엄청난 양의 데이터를 매우 빠르게 주고받도록 만든 DRAM 계열 메모리 기술이라고 이해하면 좋습니다.

GPU가 대량의 데이터를 병렬로 처리할 수 있도록 메모리 대역폭을 크게 높이는 것이 핵심입니다.

본문과의 관계를 정확히 잡기:
본문에서 RAM은 “CPU가 실행할 프로그램과 데이터를 잠시 올려놓는 공간”입니다. GPU에서는 HBM이 GPU가 계산에 사용할 데이터를 가까이에서 매우 높은 속도로 공급하는 메모리 역할을 합니다. 따라서 “RAM : CPU = HBM : GPU”라고 생각하면 입문 단계에서는 이해하기 쉽습니다.
하지만 완전히 같은 것은 아닙니다. HBM은 보통 일반적인 PC의 시스템 RAM을 그대로 대체하는 것이 아니라 GPU의 높은 데이터 처리량을 뒷받침하는 메모리입니다. 또한 HBM의 핵심 장점은 단순히 ‘용량이 크다’가 아니라 높은 메모리 대역폭입니다. GPU가 아무리 빨라도 메모리에서 데이터를 충분히 빨리 공급받지 못하면 계산 유닛이 놀게 되기 때문입니다.

8. 읽으면서 이것만 잡아보자

Q1. RAM에 필요한 페이지가 이미 있다면 페이지 히트일까, 페이지 폴트일까?

페이지 히트! 이미 RAM에 있으므로 바로 접근할 수 있습니다.

Q2. RAM이 가득 찼는데 새 페이지가 필요하다. 이때 사용하는 개념은?

페이지 교체! 기존 페이지 중 하나를 골라 내보내고 새 페이지를 넣습니다.

Q3. HBM의 핵심을 한 단어로 표현한다면 ‘용량’보다 무엇일까?

대역폭! GPU에 많은 데이터를 매우 빠르게 공급하는 것이 핵심입니다.
핵심 문장: “필요한 것만 RAM에 올리고, 없으면 가져오며, 자리가 없으면 교체한다.”
그리고 GPU 시대에는 “계산을 빠르게 하는 것만큼 데이터를 빠르게 공급하는 것”도 중요합니다.
